## 5. 明确确认后如何启动

只有用户明确确认后，才执行：

```bash
/media/sunshine/新加卷/埃斯顿比赛_2026/赛道一比赛程序/bin/train_track1_40class --execute
```

启动前仍会再次完整预检；任何一项不通过都会拒绝训练。

安全机制：

- 不加 `--execute` 只预检；
- 默认不自动回退到 CPU；
- GPU 未通过时不启动；
- 拒绝覆盖已有同名训练目录；
- 用文件锁拒绝并发训练；
- 所有缓存和临时文件写入 `cache/track1_training`；
- 训练输出只写入 `runs/track1_train_40class_v1`；
- 训练日志只写入 `logs/track1_train_40class_*.log`。

不建议普通启动方式使用 CPU。确实明确同意 CPU 训练时才使用：

```bash
/media/sunshine/新加卷/埃斯顿比赛_2026/赛道一比赛程序/bin/train_track1_40class --execute --allow-cpu
```

CPU 会使用配置中的 `cpu_profile`，速度会明显慢于 GPU。

## 7. 训练完成后的强制验收

训练脚本会自动对 `weights/best.pt` 再执行一次 val，并写入：

```text
runs/track1_train_40class_v1/<run_name>/post_train_audit.json
```

强制检查包括：

1. 最终模型仍为 `nc=40`，名称仍为 40 个。
2. 前 10 类每一类在验证结果中都必须有正 AP50。
3. 任何前 10 类缺失或 AP50 为 0，训练结果标为不可验收，脚本返回失败。

也就是说，“训练跑完”不等于“模型验收完成”；前 10 类不通过时不会允许把模型当作最终模型使用。
