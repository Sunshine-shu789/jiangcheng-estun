# 任务 C/D：自采后 30 类物品数据采集、训练与接入方案

- 文档日期：2026-10-27
- 适用范围：第三届“埃斯顿杯”大学生机器人大赛创新型赛道一，任务 C/D
- 目标：不使用官方数据集，使用现场 D405 和实际物品自行采集后 30 类（清单第 11–40 项）的 RGB-D 数据，建立可用于任务 C/D 的检测、分割、可抓性判断和现场验证链路
- 安全状态：本文仅为采集、训练、离线验证和接入方案，不代表允许实体机械臂运动
- 默认安全配置：`motion.dry_run: true`、`gripper.backend: mock`

---

## 1. 结论先行

建议采用“三条能力分开建设”的方案，而不是只把第 11–40 项物品拍成图片后合并成一个 40 类 YOLO：

1. **已知物体检测**
   - 使用 40 类检测模型；
   - 输出类别、置信度、bbox；
   - 主要服务任务 C 和任务 D 中的已知物体。

2. **类别无关物体分割**
   - 使用单类别 `object` 分割模型；
   - 不判断物体是什么，只判断“哪里是可见物体”；
   - 主要服务任务 D 中的未见物体。

3. **深度几何与可抓性判断**
   - 使用对齐后的 RGB-D；
   - 计算物体中心、主轴、短轴、估算宽度、支撑面高度、箱壁距离和遮挡程度；
   - 只有几何条件和夹爪能力都满足时，才允许进入抓取规划。

推荐数据流：

```text
D405 RGB + Depth
  ├─ 40 类已知物体检测器
  │    └─ 已知类别、bbox、置信度
  ├─ 单类别 object 分割器
  │    └─ 未知物体候选 mask
  └─ 深度几何模块
       ├─ 物体中心
       ├─ 主轴/短轴
       ├─ 夹爪开口需求
       ├─ 支撑面高度
       ├─ 箱壁净空
       └─ 时序稳定性
            ↓
       可抓性评分与目标选择
            ↓
       任务 C：已知 40 类中的可抓目标
       任务 D：已知目标 + 未见过的 object 目标
```

“不使用官方数据集”不等于“必须从零训练”。建议使用通用预训练模型做初始化，但所有训练数据、验证数据和现场测试数据均使用自采数据。

## 2. 任务 C/D 的数据目标必须分开

### 2.1 任务 C

任务 C 是在大收纳箱和小收纳箱之间进行非顺序物体抓取与放置。

数据建设重点：

- 已知 40 类物品的类别识别；
- 杂乱、重叠、部分遮挡；
- 透明收纳箱壁、箱沿、反光；
- 物体靠近箱壁时的碰撞净空；
- 从不同箱体和不同位置选择下一个可抓目标；
- 抓取后放到另一箱体的目标区域。

任务 C 不能只看整体 mAP，还要看每一类的 recall、混淆矩阵和真实抓取成功率。

### 2.2 任务 D

任务 D 与任务 C 类似，但目标是未见过的物体。

关键原则：

- **D 的泛化能力不能用训练过的物体证明**；
- 必须保留完全未参与训练的实物类别或物理实例；
- `object` 分割器应采用 leave-one-category-out 方式验证；
- 现场随机加入的物体必须由类别无关分支产生候选，不能强行归类到 40 类之一；
- 未知物体只有在 mask 稳定、深度有效、抓取宽度和箱壁净空满足条件时才允许尝试。

### 2.3 不要混淆“采集”和“训练”

后 30 类都可以采集入库，但这不等于全部 30 类都必须进入最终模型训练：

- 为训练 C，可以在最终阶段使用全部已知 40 类；
- 为验证 D，必须保留训练时从未见过的类别或实例；
- 建议另找 10–20 个不在 40 类清单中的随机物品，作为 D 的最终盲测集；
- 如果训练资源允许，使用多折 leave-one-category-out 训练/验证，不要只做一次随机切分。


如果采集时机械臂不动，`robot_pose` 可填写固定观察位姿或留空；一旦相机或机械臂位置改变，必须记录对应的机器人位姿和变换来源。

### 4.3 图像和深度规范

- 彩色图保存为 PNG，不保存有损 JPEG；
- 深度保存为 16-bit PNG 或 `.npy`，无效值为 0；
- 彩色图和深度图必须来自同一对齐帧；
- 保存经过正式推理相同 `rotate_180` 变换后的图像、深度和内参；
- 内参必须记录为变换后的最终值；
- 训练和推理使用相同的 D405 分辨率、焦距、裁剪和旋转；
- 每批数据计算并保存 SHA-256 校验清单。

当前正式现场配置使用 640×480、15 FPS、`rotate_180: true`。如果后续改变分辨率或旋转，必须建立新数据集版本并重新验证模型，不可直接沿用旧标签。

## 5. 采集环境与安全要求

### 5.1 相机

- 使用正式 D405；
- 固定相机串口和安装方式；
- 固定曝光、白平衡和图像尺寸；
- 采集期间不要随意改变相机位置；
- 使用正式或最新完成的手眼标定文件；
- 当前 `track1_live.yaml` 仍引用 `camera_to_flange.d405_assumed.yaml`，正式 3D 数据接入前必须改为已验证的标定文件，例如 `camera_to_flange.d405_calibrated_20261025.yaml`；
- 标定文件和采集数据中的内参、旋转状态必须一致。

### 5.2 采集场景

必须使用与比赛一致的：

- 工作台面和背景；
- 大收纳箱；
- 小收纳箱；
- 现场光源或接近现场的光源；
- 实际 D405 安装高度和观察角度。

至少采集以下场景：

1. 空台面；
2. 空小箱；
3. 空大箱；
4. 单物体台面；
5. 单物体小箱；
6. 单物体大箱；
7. 多物体杂乱台面；
8. 多物体大小箱；
9. 物体靠近箱壁；
10. 物体部分遮挡或相互重叠；
11. 物体在不同光照和反光条件下；
12. 物体从一箱转移到另一箱前后的场景。

### 5.3 安全边界

采集阶段只运行相机和深度采集程序：

- 不调用 `run_task_c`；
- 不调用 `run_task_d`；
- 不发送机械臂运动命令；
- 不发送夹爪命令；
- 保持 `motion.dry_run: true`；
- 保持 `gripper.backend: mock`。

如果为了获得不同视角需要移动机械臂，必须由用户明确确认，并由维护人员使用示教器或经过批准的低速安全流程完成。采集脚本本身不得自动运动。

## 6. 采集矩阵与数量建议

### 6.1 总体数量

建议目标：

- 总帧数：8,000–12,000 帧；
- 可见物体实例：20,000 个以上；
- 负样本/空场景：10% 左右；
- 每类可见实例：至少 200–300 个；
- 透明、软体、小目标：适当增加数量。

最低可用基线：

- 3,000–5,000 帧；
- 8,000–10,000 个可见实例；
- 300–500 个空场景/负样本；
- 足够完成一次端到端试点，但不能据此声称已达到现场稳定水平。

### 6.2 推荐采集表

| 场景 | 推荐数量 | 目的 |
|---|---:|---|
| 30 类单物体台面 | 30 类 × 30–50 帧 | 类别外观、基本姿态 |
| 单物体小箱 | 30 类 × 10–20 帧 | 透明箱壁、边角、深度干扰 |
| 单物体大箱 | 30 类 × 10–20 帧 | 远距离和箱内场景 |
| 多物体杂乱台面 | 1,000–2,000 帧 | 重叠、遮挡、类别混淆 |
| 多物体大小箱 | 1,000–2,000 帧 | C/D 核心场景 |
| 空箱、空台面、干扰物 | 300–800 帧 | 降低背景误检 |
| D 盲测随机物 | 10–20 个物体 × 50–100 帧 | 未见物体泛化验证 |

### 6.3 每个物体的姿态覆盖

每个物体至少覆盖：

- 正放、倒放、侧放、倾斜；
- 水平旋转 0°、45°、90°、135°；
- 中心、靠近箱角、靠近箱壁；
- 单独放置；
- 与其他物体接触；
- 部分遮挡；
- 正常光、强反光、偏暗；
- 大箱和小箱两种容器。

### 6.4 分材料采集要点

- **Padlock、Key、Nail、Dice、Adapter、Screwdriver**
  - 目标较小，必须保证在 640×480 中占据足够像素；
  - 增加近距离、中心区域和小目标样本；
  - 检查深度是否存在大量空洞。

- **Wine Glass、Plastic White Cup、Scotch Tape、可乐瓶**
  - 透明或半透明，深度可能穿过物体看到背景；
  - 必须采清晰的 RGB 边缘、轮廓和反光；
  - 训练 mask 时不要将箱壁、桌面和反光区域标成物体；
  - 透明物体无法可靠估计深度时，可抓性应降低或拒绝，而不是强行运动。

- **T-shirt、Glove、Paper Towels**
  - 采集折叠、摊开、堆积、边缘翘起等状态；
  - 不能只采完全平铺；
  - 注意柔性物体变形导致的 mask 不稳定。

- **Wrench、Spoon、Bowl、Mug**
  - 金属反光明显，要采高光和低光；
  - 采正放、倒放、侧放和边缘遮挡；
  - 注意类别之间的形状混淆。

- **Coca_cola_half、Coca_cola_full、Pringles、Book**
  - 采不同旋转方向和包装反光；
  - 注意圆柱和平面物体的抓取中心、主轴和倾斜姿态。

## 7. 采集操作流程

### 7.1 单次采集会话

1. 固定相机、箱子、灯光和机器人观察位。
2. 先拍 20–50 帧空场景。
3. 摆放一个物体，记录物体 ID。
4. 手动改变姿态和位置，每改变一次后等待图像稳定再保存。
5. 对每个稳定姿态保存 RGB、深度和元数据。
6. 换下一个物体；同类多件记录唯一 `instance_id`。
7. 采多物体杂乱场景，随机混放 3–10 个物体。
8. 分别在台面、小箱、大箱中重复。
9. 清理现场前拍摄空箱和空台面负样本。
10. 生成本次会话报告和 SHA-256 清单。

不要只保存连续视频的每一帧。相邻帧高度重复，会增加标注成本并造成数据泄漏。建议在静止状态触发保存；视频仅作为备份或用于筛取少数运动/遮挡帧。

### 7.2 试点优先

不要一次采完 30 类。先取 6 个代表物做闭环：

- Padlock：小金属刚性物；
- Baseball：曲面物体；
- Dice：小尺寸物体；
- Wine Glass：透明物体；
- Scotch Tape：透明、反光、扁平物体；
- T-shirt：柔性物体。

试点流程：

1. 每类采 30–50 帧；
2. 标注 bbox 和 object mask；
3. 训练一个很小的检测/分割基线；
4. 检查透明物、箱壁、深度缺失和小目标问题；
5. 试点通过后再按每批 5 类扩展。

## 8. 标注规范

### 8.1 已知物体检测标注

使用 YOLO detection 格式：

```text
class_id x_center y_center width height
```

规则：

- bbox 紧贴可见物体；
- 不把透明箱壁、反光、桌面框入；
- 被遮挡物只标可见区域；
- 每帧记录 `scene_id` 和 `instance_id`；
- 同一物体在连续帧中的示例不能跨越 train/val/test；
- 对边界模糊的透明物体，宁可标注可见轮廓，也不要猜测不可见体积。

### 8.2 类别无关分割标注

为单类别 `object` 模型准备 mask：

- 所有物体类别统一标为 `object`；
- 只标可见区域；
- 排除箱壁、箱沿、桌面、反光和相机自身结构；
- 透明物体轮廓不清时，记录 `mask_quality` 和 `occlusion_level`；
- 允许保留少量质量较低的样本，但训练时必须有权重或过滤。

建议使用 CVAT、Label Studio 或 SAM 类模型辅助生成初始 mask，再人工修正。自动 mask 不得未经复核直接进入最终训练集。

### 8.3 抓取标注

建议只对一部分帧标注抓取信息：

```text
grasp_u
grasp_v
grasp_angle_deg
jaw_width_m
approach_direction
quality
```

`quality` 可定义为：

- 3：稳定中心/平面抓取；
- 2：可抓但需要调整姿态；
- 1：边缘或高风险抓取；
- 0：不可抓或碰撞风险高。

如果后续进行真实抓取试验，每次试验记录：

- 目标 ID；
- 抓取点；
- 夹爪开口；
- 是否夹住；
- 抬起后是否保持；
- 是否碰撞箱壁；
- 失败原因。

真实试验数据优先级高于人工猜想的抓取标签。

### 8.4 箱体标注

C/D 不只需要物体数据，还需要箱体数据：

- 空箱图像；
- 大箱和小箱箱角、箱沿、内壁；
- 放置目标区域；
- 箱壁与物体的距离；
- 空箱负样本；
- 多个视角下的箱体位姿。

可以在 mask 模型之外单独增加 `box` 类别，或使用独立的箱体检测/位姿拟合模块。不要把所有箱体像素混入 `object` 类别。

### 8.5 标注质量检查

每批数据至少检查：

- 10% 随机双人复核；
- bbox 是否紧贴可见物体；
- mask 是否误包含箱壁和反光；
- 类别标签是否一致；
- instance_id 是否重复或缺失；
- 空场景是否有误标；
- 透明物、软体物和小物体是否被系统性漏标；
- 同一场景是否同时出现在 train 和 test。

## 9. 数据集划分与防泄漏

### 9.1 按场景和实例分组

禁止按连续帧随机切分。必须按以下分组：

```text
scene_id
object_id / instance_id
采集日期
背景
箱体
灯光条件
```

推荐比例：

```text
train      70%
val        15%
test       15%
```

同一个场景的全部帧只能进入一个集合；同一个物理实例应尽量只进入一个集合。

### 9.2 任务 C 的划分

- 训练集覆盖所有已知 40 类；
- 验证集按类别和场景分层；
- 测试集使用独立场景和独立摆放；
- 每类至少保留一部分未参与训练的物理实例用于测试；
- 透明物和软体物单独统计，不只汇报总体平均值。

### 9.3 任务 D 的划分

必须建立真正的盲测集：

- 预留 5–10 个类别完全不参加训练；
- 另准备 10–20 个不在 40 类清单中的随机物品；
- 这些物品的 RGB、深度、mask 和抓取尝试只用于验证；
- 对 object 分割模型采用 leave-one-category-out；
- 训练清单、验证清单和盲测清单分别做成不可变 manifest。

如果所有 30 类最终都要进入 C 的训练，仍然需要另找 D 盲测物品，否则无法证明未见物体的泛化能力。

## 10. 模型训练方案

### 10.1 模型 1：40 类已知检测器

用途：

- 任务 C 的已知物体检测；
- 任务 D 中已知物体的高置信度识别。

建议：

- YOLO detection 模型；
- 40 类输出；
- 从通用预训练权重初始化；
- 输入尺寸 640，和现有部署配置一致；
- 训练时保留前 10 类标签不变；
- 训练后输出 `models/track1_known_40_v001.pt`。

建议初始超参数：

```yaml
imgsz: 640
epochs: 80-150
optimizer: AdamW
lr0: 0.001
lrf: 0.01
weight_decay: 0.0005
batch: 8-16
patience: 20
mosaic: 0.5
degrees: 180
translate: 0.1
scale: 0.3-0.5
hsv_h: 0.015
hsv_s: 0.3-0.4
hsv_v: 0.3-0.4
```

根据显存和训练速度调整 batch，不要为了增大 batch 牺牲输入分辨率。

### 10.2 模型 2：单类别 object 分割器

用途：

- D 的未知物体候选；
- 已知检测置信度低时的兜底；
- 为深度几何模块提供 object mask。

建议：

- 单类别 YOLO segmentation；
- 标签统一为 `object`；
- 透明、软体、小目标都要有足够样本；
- 输出 `models/track1_object_seg_v001.pt`；
- 对未知类别做 leave-one-category-out 验证。

### 10.3 增强策略

可使用：

- 亮度、对比度、HSV 变化；
- 轻度模糊、噪声；
- 随机遮挡；
- 小目标过采样；
- 多物体 copy-paste；
- 旋转、缩放、裁剪；
- 透明物体边缘增强；
- 箱壁附近困难样本采样。

不建议：

- 用过度几何变形破坏夹爪宽度和深度关系；
- 只用同一背景的重复帧；
- 只用同一物理实例做所有增强；
- 用有损压缩后反复保存；
- 把验证集图像参与训练增强。

### 10.4 训练后必须输出的报告

- 每类 precision/recall/AP；
- 混淆矩阵；
- 小目标单独统计；
- 透明物单独统计；
- 空场景误检率；
- object mask IoU；
- D 盲测物体召回率；
- 端到端单帧延迟；
- 失败案例图像清单。

## 11. 与当前程序的接入要求

当前代码核对结果：

- `config/track1_live.yaml` 的 `vision.classes` 目前只有前 10 类；
- `YoloDetector` 会按 `vision.classes` 过滤模型输出；
- `RealSenseYoloVision._make_detection()` 当前把 `graspability` 固定为 `1.0`；
- `target_support_guard_mask()` 目前只对 banana 返回颜色 mask；
- 任务 C 的默认策略是 `any`，任务 D 默认是 `known_and_unseen`；
- `pose.extrinsics_file` 当前仍指向 assumed 标定文件。

因此，训练完模型后不能只改权重路径，还必须完成以下接入工作。

### 11.1 扩展类别配置

将 `vision.classes`、`target.known_classes`、`target.order`（如任务 E 使用）统一扩展为 40 类。

要求：

- 标签字符串完全匹配训练模型 `names`；
- 不使用数字索引猜测类别；
- 不改动前 10 类现有标签；
- 用 `class_map.yaml` 生成配置并校验配置和模型标签一致。

### 11.2 增加 object 分支

建议在配置中增加类似字段：

```yaml
vision:
  known_weights: ../models/track1_known_40_v001.pt
  object_weights: ../models/track1_object_seg_v001.pt
  unknown_labels: [object]
```

如果暂时不做双模型，也可以使用一个 40+object 类模型，但必须满足：

- known 类优先；
- object 类不能被误当成已知类；
- NMS 后不能出现同一物体的重复已知框和 object 框；
- D 的未知物体测试不能只用已知类训练结果来证明。

### 11.3 修改 graspability

不能继续使用固定值：

```python
graspability=1.0
```

应根据以下因素计算：

- mask 置信度和时序稳定性；
- 有效深度比例；
- 点云数量；
- 物体估算宽度与夹爪最大开口；
- 物体高度和支撑面；
- 物体到箱壁的最小距离；
- 物体到图像边缘的距离；
- 遮挡程度；
- 抓取路径的碰撞风险。

建议设置硬门槛和软分数两层：

- 硬门槛不满足，直接拒绝；
- 软分数用于多个候选目标之间排序。

### 11.4 修改目标策略

- 任务 C 如果只允许已知 40 类，建议策略为 `known`，不要用无条件的 `any`；
- 任务 D 使用 `known_and_unseen`；
- `unknown_labels` 建议统一为 `[object]`；
- 已知类低置信度时不要强行归类，应进入未知候选分支；
- 同一场景选择目标时，分数应包含可抓性和碰撞惩罚，而不是只看检测置信度。

当前 `apply_mode()` 将 C 映射为 `any`，需要在正式接入时改为可配置策略或显式改为 `known`。

### 11.5 增加 mask 数据

当前 `Detection` 主要包含 bbox、深度和几何轴，没有完整 object mask。

建议增加：

- `object_mask`；或
- mask RLE；
- `mask_quality`；
- `occlusion_level`；
- `box_wall_clearance_m`。

时序稳定器也应增加 mask IoU 或 mask 中心稳定性检查，不能只用 bbox 匹配。

### 11.6 正确使用标定文件

C/D 真实抓取前必须：

- 使用已验证的手眼标定；
- 确认相机旋转 180° 后的内参；
- 检查相机坐标到法兰坐标的旋转和平移方向；
- 对已知台面点进行投影核对；
- 在 `dry_run` 下检查规划点是否落在实际物体附近；
- 不把 assumed 标定结果用于真实抓取。

### 11.7 箱体放置目标

当前通用配置中的固定 `place_pose` 不能完整覆盖 C/D 的大小箱转换。

需要增加或标定：

- 大箱/小箱的位姿；
- 箱内安全放置区域；
- 箱壁和夹爪的净空；
- 放置前的碰撞检查；
- 放置后的退让路径。

数据采集中必须同步采集空箱和箱沿图像，否则视觉模型只能识别物体，无法支持箱间放置。

## 12. 验收方案

### 12.1 离线验收

建议内部门槛：

| 项目 | 目标 |
|---|---:|
| 40 类检测 mAP50 | ≥ 0.90 |
| 40 类检测 mAP50-95 | ≥ 0.70 |
| 每类 recall | ≥ 0.85–0.90 |
| 空场景误检率 | ≤ 3–5% |
| object mask IoU | ≥ 0.75 |
| D 盲测物体召回率 | ≥ 0.85 |
| 透明物 mask/抓取成功率 | 单独统计，不能只报总体 |
| 检测+深度处理延迟 | ≤ 100–150 ms |

这些是初始门槛，不是比赛成绩承诺；透明物、软体物和小目标可以单独设置更严格或更宽松的门槛，但必须在报告中写明。

### 12.2 真实场景测试

必须先完成离线测试，再进行真机测试：

1. `motion.dry_run: true`、`gripper.backend: mock`；
2. 只做检测、分割、深度和规划点检查；
3. 使用假执行或离线回放检查抓取中心；
4. 经用户明确确认后，才允许进行低速单物体真机测试；
5. 每次真机测试必须有维护人员守急停；
6. 测试顺序建议：
   - 单个刚性物体；
   - 单个透明物体；
   - 单个软体物体；
   - 3–5 个杂乱物体；
   - 大箱/小箱间转移；
   - 未见物体候选。

### 12.3 每次验收必须保存

- 数据版本；
- 模型文件 SHA-256；
- 配置文件和标定文件；
- 测试场景和物体 ID；
- 每帧检测结果和 mask；
- 抓取成功/失败原因；
- 碰撞或中止记录；
- 端到端耗时；
- 失败案例截图。

全部日志和报告放在正式数据盘的 `logs/` 或 `reports/` 下，不写回主目录。

## 16. 一句话执行原则

先用少量代表物打通“D405 采 RGB-D → 标注 → 检测/分割 → 深度可抓性 → dry-run 规划”的闭环，再批量采集 30 类；任务 C 依靠已知 40 类检测，任务 D 依靠类别无关 object 分割和真实盲测，不能仅靠增加 30 个训练类别来假装实现“未见物体”能力。
