赛道一比赛程序
================

这个文件夹包含赛道一程序代码、模型、配置、日志和五个独立任务启动程序。
任务A固定使用旧的“视觉识别”；任务B/C/D/E使用新的抓取识别、IK、运动和状态机核心。
任务C和任务D是两个分别启动、分别配置、分别验收的程序；可以共享底层库，但不得合并启动或互相代替验收。

一、启动任务
------------
直接双击对应程序，不需要在终端输入命令：

  任务A_十点位巡检.desktop
  任务A_视觉识别.desktop
  任务B_五点位拾放.desktop
  任务C_无序抓取.desktop
  任务D_未知物体抓取.desktop
  任务E_顺序抓取.desktop

辅助入口“机械臂速度调节.desktop”只调整速度比例，不启动任务、不移动机械臂，
具体用法见第三节。

任务A有两个入口：

1. 任务A_十点位巡检.desktop
   - 机械臂以启动时的六轴位姿为起点，巡检10个停点位，最后自动回到启动
     时的精确关节姿态。
   - J1以启动位置为锚点左右分配完整270°，两条弧各有5个点：第1弧扫到一侧
     端点，第2弧反向扫回。程序先让左右各请求135°；若一侧先触及控制器安全
     限位，该侧使用全部可用安全行程，由另一侧补足剩余跨度。当前起点
     J1≈93.324°时，右侧可用104.676°、左侧分配165.324°，范围为
     [-72°, +198°]，总跨度仍为270°，不会锁死在93.324°中心。
   - 第1弧的J2相对启动姿态 +15°，第2弧的J2相对启动姿态 -9°；第5点到
     第6点保持J1在同一端，通过J2的24°切换形成两条半径弧。
   - J1-J4允许运动，当前点位由J1和J2完成双弧巡检；J5、J6在每个目标中
     精确复制启动反馈并全程锁定，避免夹爪腕部关节动作。
   - 启动后先一次性预检查10个巡检点和第11个“回启动位”目标，包括FK、
     工作空间、关节限位、单步角度和TCP相邻距离。任何一项失败都不会发送
     第一段运动命令。
   - 固定读取旧版“任务A 视觉识别”的实时结果，不启动新的“抓取识别”，
     也不加载 models/best.pt。
   - 十类比赛物品全部纳入识别范围：Cheez-it、Starkist_Tuna、Scissors、
     Frenchs_Mustard、Tomato_Soup、Foam_Brick、Clamp、Plastic_Banana、
     Mug、meat_can。
   - 每个点位最多观察10秒，连续3帧确认十类中的任意物品后，机械臂在原地
     停3秒，再自动前往下一点；不会等待操作员按回车，也不会因为物品一直
     可见而重复运动或死锁。
   - 某点10秒内没有确认物品时，程序记录该点未命中并继续下一点；只有相机、
     旧视觉HTTP或机械臂通信故障才中止任务。
   - 该巡检入口不会发送夹爪命令。

2. 任务A_视觉识别.desktop
   - 打开旧版“视觉识别”，只做相机识别和观察。
   - 不移动机械臂，适合现场快速确认相机和模型。

任务B的五轮流程：
- 每一轮只抓取视觉确认过的当前点位物品。
- 开局先观察当前视野；未确认香蕉时，机械臂会依次移动到当前点位上方的
  多个安全观察位置继续寻找，每到一个位置重新识别。搜索不到时回到初始
  观察位姿，不会因为单帧误识别而直接抓取。
- 抓取后回到本轮实际抓取位置释放，不移动到固定投放槽。
- 释放并退开完成后，才等待视觉确认下一个点位的物品。
- 旧点位仍能看到已放回物品时，不会开始下一轮，也不会发送下一轮运动命令。
- 下一点没有确认时持续等待；任务停止或故障时才退出。
- 五个点位全部完成后程序退出。

任务C和任务D是两个独立任务程序：
- 任务C_无序抓取.desktop -> bin/run_task_c
  只抓V11已知40类；unknown/object一律拒绝，未知物proposer关闭。
- 任务D_未知物体抓取.desktop -> bin/run_task_d
  接受已知40类和高可抓性unknown/object，未知物proposer开启。
- 必须先把任务C做完并验收通过，再开始任务D。
- 任何时刻只能运行C或D中的一个，不能同时打开；底层视觉、IK、运动和状态机
  库共用不代表任务可以合并。
- 任务C正式配置的抓取后法兰Z抬升为 0.1706 m：最低抓取位实测 D405 光学中心到
  收纳盒底部约 0.179600 m，抬升后约为 0.35 m。该值不是垂直抬升 0.35 m。
- Task C/D 主笛卡尔运动速度为 0.03 m/s，是原 0.01 m/s 的 3 倍；视觉伺服
  servo.speed_mps 仍保持 0.01 m/s，两类运动不得混为一谈。

任务B/C/D/E的共用运行特性：
- 启动后自动使用新的持续实时识别，机械臂搜索、运动、靠近和夹取期间
  识别窗口都会持续刷新，可以一直观察。
- 桌面的“抓取识别”也可单独打开，用于手动观察；它本身不会移动机械臂。
- 任务运行时不要同时打开“视觉识别”或单独的“抓取识别”，D405只能由
  一个程序占用。

二、停止任务
------------
正常停止：双击“停止当前任务.desktop”。
该入口会停止当前任务、旧版“视觉识别”和单独的“抓取识别”。
紧急停止：立即按下机械臂硬件急停按钮。

三、机械臂速度调节
------------------
双击“机械臂速度调节.desktop”，选择任务A/B/C/D/E后调整速度比例；
每个任务分别保存，互不影响。界面同时显示当前主运动速度、关节速度上限和
该任务100%时的安全上限。

安全规则：
- 可调范围固定为10%–100%，不提供0%；零值、负值、NaN、无穷大和损坏的
  状态数据都不会传给运动控制器。
- 100%不是额外超频，而是该任务正式配置中已经验证的安全速度。实际请求始终
  同时受正式配置上限和界面比例限制，任何状态文件都不能突破配置值。
- 当前100%安全上限：任务A主运动0.020 m/s，任务B 0.010 m/s，任务C
  0.030 m/s，任务D 0.030 m/s，任务E 0.010 m/s；五个任务关节速度上限
  均为0.600 rad/s。
- 保存后从下一段运动开始生效；已经下发、正在执行的轨迹不会临时改变。
- 低速路径会按实际速度延长轨迹超时，但仍有900秒硬上限。超时、反馈丢失或
  控制器故障会按异常停止，不会通过零速度或无限等待来规避锁死。
- 调节工具不导入ROS、不启动任务、不取得task.lock，也不构成运动授权。
- 状态保存在state/arm_speed_overrides.json。不要手工编辑；文件缺失或损坏时
  按100%正式安全值启动，Task B仍保持motion.dry_run: true和夹爪mock。
- 硬件急停始终是最终保护，软件调速不能替代现场值守和急停。

维护人员可在终端只读检查五个任务的当前比例与上限：

  /media/sunshine/新加卷/埃斯顿比赛_2026/赛道一比赛程序/bin/arm_speed_control --check

四、当前安全状态
----------------
任务A正式入口使用 config/track1_task_a_legacy.yaml，当前
motion.dry_run: false，属于真机模式。双击后必须先在安全确认窗口确认控制器
处于 AutoReady、无故障、急停可用且工作区无人，程序才会继续。
- 十点位路线、最后回原点和J5/J6锁定会在第一段运动前全部预检查；
- 预检查或通信检查失败时，机械臂不会运动；
- 任务A巡检本身不会发送夹爪命令，夹爪保持当前状态；
- 程序内置配置和自动测试使用 dry-run 副本，不用于现场启动。

每次启动任务前程序都会进行环境检查。同一时间只允许一个任务运行，避免两个
任务同时抢占相机和机械臂。

任务A巡检和B/C/D/E启动时，程序会自动检查机械臂状态桥接：
- 桥接已运行时不重复启动；
- 桥接未运行时自动启动，并等待 /RobotInfo 到位；
- 本次任务启动的桥接会在任务结束后自动关闭；
- 若 12 秒内收不到状态，会弹出错误窗口，不再直接以一个一闪而过的
  英文异常结束。
控制器侧需保持“设置 -> ROS”的目标 IP 指向本机 UDP 9006 端口。

五、任务A十点位巡检参数
------------------------
在 config/track1_task_a_legacy.yaml 的 task_a.patrol 中设置：

  mode: joint_arc                  使用关节双弧巡检
  position_count: 10               共10个停点位
  movable_joints: [1, 2, 3, 4]     J1-J4允许运动
  joint1_relative_targets_deg:     J1相对锚点的双弧轮廓（运行时左右分配）
    [135, 67.5, 0, -67.5, -135,
     -135, -67.5, 0, 67.5, 135]
  joint_offsets_deg:               J2/J3/J4相对启动姿态偏置
    第1弧 [15, 0, 0]，第2弧 [-9, 0, 0]
  min_move_distance_m: 0.15        相邻TCP最小距离
  joint_max_step_deg: 2.0          关节插补单步上限
  settle_s: 0.5                    到位稳定时间
  post_detection_dwell_s: 3.0      确认物品后原地停留时间
  return_to_start: true            第10点后回到启动关节位姿

六、真机启用
------------
完成手眼标定、真实夹爪接线和现场安全验证后，由维护人员逐项检查：

  任务A：config/track1_task_a_legacy.yaml
  任务B：config/track1_task_b_live.yaml
  任务C：config/track1_task_c_v11_official_20261102.yaml
  任务D：config/track1_task_d_v11_official_20261102.yaml
  任务E：config/track1_live.yaml

验收前必须确认：
  1. 未验收任务保持 motion.dry_run: true 和 gripper.backend: mock；只有该任务
     的现场验收全部通过并获明确运动授权后，才允许改为 false/真实夹爪。
  2. gripper.backend 与现场夹爪一致，开合方向、行程和反馈阈值已验证。
  3. pose.extrinsics_file 指向已验证的正式手眼标定文件。
  4. task_b_place_poses.yaml 已按现场五个抓取点核对。
  5. target_order.yaml 和任务E顺序一致。
  6. C、D 分别验收；C 未通过时不得用 D 的配置试跑，且两者不能同时启动。

之后双击任务程序时，会先弹出真机安全确认窗口：
确认控制器为 AutoReady、无故障、急停可用、工作区无人后，点击“开始任务”。

七、目录说明
------------
bin/      五个任务启动程序和公共启动器
app/      完整程序源代码
config/   相机、机械臂、夹爪和任务配置
models/   B/C/D/E新的抓取识别模型（任务A不使用）
logs/     每次任务的终端日志和截图
state/    当前运行任务的进程状态和机械臂速度比例

八、重要限制
------------

旧视觉HTTP适配和十类覆盖统计已经完成自动测试及离线起点预检。
