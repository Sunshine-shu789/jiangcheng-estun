# Task B YOLO 输入尺寸与腰部运行依赖修复（2026-11-06）

## 结论

18:51 的低速 `pick_1` 实机尝试没有进程卡死。机械臂已到达观察位，任务在
30 秒内连续得到 8 帧 YOLO 零检测后按设计超时退出，未进入下降、夹爪闭合或
释放阶段。

## 根因

1. `models/best.pt` 的 checkpoint 记录训练尺寸为 `imgsz=640`，但三个当前
   Task B 配置错误地使用了 `imgsz=960`。
2. 对 18:52 的真实诊断帧离线复跑：
   - `imgsz=640`: `8-Plastic_Banana=0.931741`
   - `imgsz=960`: 原始 YOLO 输出为 0 个框
3. 现场运行时加载的 OpenCV 5 不包含 `ximgproc`。即使恢复 YOLO 检测，原腰部
   中心线算法仍会在细化阶段 fail-closed。

## 修复

- 将正式五点配置、低速单点和快速单点配置的 `vision.imgsz` 改为 `640`。
- 启动时读取 checkpoint 的训练尺寸；配置与 checkpoint 不一致时直接报错，
  不再静默跑到零检测超时。
- 增加内置 Zhang-Suen 细化后备，不再依赖 OpenCV contrib 的
  `ximgproc.thinning`；存在 contrib 时仍优先使用原有实现。
- 增加配置、尺寸保护和细化后备回归测试。

## 验证

- 离线真实诊断帧：640 下稳定输出香蕉框，置信度 `0.931741`。
- 相机只读原始检测连续 5 帧：香蕉置信度 `0.717` 到 `0.925`。
- 完整视觉只读链路连续 8 帧：第 3 帧起连续 6 帧稳定输出
  `adaptive_axis_source=waist_midline`，腰部中心和局部短轴均有效。
- 完整测试：`1049 passed in 111.71s`。
