# GraspNet 夹爪开口搜索多帧离线验收报告

日期：2026-10-31  
状态：**离线链路完成并形成 5 帧抓取共识；覆盖与现场验证不足，暂不授权真机抓取**

> 安全边界：`offline_only=true`、`motion_attempted=false`、`hardware_connected=false`、`motion_authorized=false`。本批仅读取已采集 RGB-D 数据，未连接或控制实体机械臂、夹爪、控制柜或相机。

## 1. 结论

- 批次内 `20/20` 帧完成，`0` 个评分错误，所有帧 stderr 为空。
- `20/20` 帧通过离线安全边界检查；`20/20` 帧支撑平面估计有效。
- `10/20` 帧产生最终几何候选（覆盖率 `50.0%`），`8/20` 帧产生 IK 成功候选（`8` 个成功候选）。
- 全批共有 `22` 个通过接触/CAD/世界净空的最终候选；经 NMS 后保留 `12` 个，实际 IK 评估 `12` 个，成功 `8` 个，IK 成功率为 `66.7%`。
- 使用“至少 4 个独立帧 + TCP 平移 25 mm + 平行夹爪对称旋转 15°”的完整连通共识门禁后，帧 `9, 12, 14, 15, 19` 形成唯一通过簇，共 `5` 个候选、`5` 个独立帧；代表候选为 `frame_19/graspnet_00050`。
- 另外 `3` 个 IK 成功候选（帧 `11, 22, 23`）没有达到 4 帧共识门禁，按 fail-closed 规则不纳入可复用抓取。
- 本轮证明 GraspNet + 开口搜索 + CAD/净空 + NMS + IK + 多帧共识的离线链路可运行，且没有安全边界违规；但 `5/20` 的共识覆盖率、单场景验证和未标定的手眼/夹爪参数仍不足以支持真机抓取。

## 2. 从 GraspNet 得到的关键优化结论

- **GraspNet 的 `width` 只能作为参考宽度/开口上限，不能直接作为夹爪最终闭合开口。** 本批 `GraspNet 参考宽度直接可评分` 的候选只有 `1` 个，但通过开口搜索最终得到 `8` 个 IK 成功候选；如果直接把参考宽度当开口，链路几乎无法工作。
- 共评估 `5120` 个 GraspNet 候选，执行 `80862` 次开口搜索试算（平均每个候选 `15.79` 次）；其中 `126` 个通过局部评分，`22` 个通过世界净空，说明开口搜索是必要的，但世界净空和 IK 仍是主要瓶颈。
- 8 个 IK 成功候选的参考宽度为 `49.11–61.83 mm`，实际选择开口为 `33.08–38.12 mm`，参考宽度明显高于最终几何所需开口；选择开口不能由网络宽度替代 CAD 几何评估。
- 没有通过放宽接触、碰撞、净空或 NMS 阈值来换取结果；失败帧保持失败，这是正确的 fail-closed 行为。

## 4. IK 结果

- IK 评估 `12` 个，成功 `8` 个；失败 `4` 个。
- 失败集中在帧 16、20、22：帧 16 的 2 个 NMS 保留候选全部失败；帧 20 的 1 个候选失败；帧 22 有 2 个候选，其中 1 个成功、1 个失败。
- 帧 16 和 20 存在明显的姿态收敛失败（末端姿态误差约 `0.28 rad`、位置误差约 `19 mm`）；帧 16 的另一个候选和帧 22 的一个候选已接近收敛但仍未通过严格 IK 门限。不能仅凭“接近收敛”将其算作成功。
- IK 成功只表示诊断性逆解收敛，不等于整臂运动规划、奇异点穿越、完整碰撞检查或真机可执行。

## 6. 多帧抓取共识结果

### 6.1 门禁定义

- 输入只允许已经同时满足 `final_feasible=true`、`nms_kept=true`、`ik.success=true`、`ik.at_joint_limit=false` 的候选。
- 每个候选使用基座系 `T_base_tcp` 的 TCP 位置和姿态；旋转距离允许平行夹爪绕接近轴 `180°` 翻转等价。
- 至少需要 `4` 个独立帧；同一个帧内出现多个候选不能增加独立帧数。
- TCP 平移容差为 `25 mm`，夹爪对称旋转容差为 `15°`。
- 使用完整连通聚类：簇内任意两个候选都必须同时满足两个容差，禁止通过中间候选链式放宽。
- 共识不足时直接 fail-closed，不回退到单帧偶然成功，也不降低原有 CAD、碰撞、净空、NMS 或 IK 门限。
- 共识报告的 `motion_authorized` 永远为 `false`。

### 6.2 结果

| 项目 | 结果 |
|---|---|
| 输入帧 / 安全标记通过 / 计数完整性通过 | `20 / 20 / 20` |
| NMS 保留 / IK 评估 / IK 成功 | `12 / 12 / 8` |
| 纳入共识聚类 | `8` |
| 共识簇 / 通过簇 | `4 / 1` |
| 通过簇帧号 | `9, 12, 14, 15, 19` |
| 通过簇候选数 / 独立帧数 | `5 / 5` |

| 簇内中位质量 | `0.7739` |
| 实际开口范围 | `34.67–36.40 mm` |
| GraspNet 参考宽度范围 | `49.11–59.15 mm` |
| TCP 基座系质心 | `[-0.047473, 0.510328, 0.027063] m` |

该簇的 5 个候选姿态按夹爪对称距离完全一致，TCP 位置最大两两偏差为 `21.39 mm`，低于 `25 mm` 门禁。开口范围为 `34.67–36.40 mm`，再次说明 GraspNet 参考宽度不能直接替代实际闭合开口。

### 6.3 未通过共识的 IK 成功候选

- 帧 `11`：与主簇平移最近约 `1.12 mm`，但夹爪对称旋转差约 `23.89°`，超过 `15°`。
- 帧 `22`：与主簇旋转差约 `26.59°`，作为单帧簇拒绝。
- 帧 `23`：与主簇旋转差约 `16.97°`，作为单帧簇拒绝。
- 帧 `22` 与帧 `23` 互相仅相差约 `7.10 mm / 15.00046°`，但旋转仍严格超过 `15°` 门禁，因此没有通过；本轮没有为了让它们合并而修改阈值。

### 6.4 解释边界

多帧共识只证明 TCP 位姿在独立帧中重复出现，不证明以下事项：

- 候选接触的是同一块物体表面或同一接触区域；
- IK 解属于同一关节分支，或整臂路径一定可达；
- 已通过完整网格、整臂、环境和动态障碍碰撞检查；
- 实机夹爪安装时钟、垫片、指零位、TCP 和手眼外参已标定；
- 抓取成功率或抓取质量已经得到真实数据验证。

因此，该共识结果是一个离线稳定性门禁，不是运动授权。

## 7. 建议的下一步

1. **接入 Mock / dry-run**：把 aperture search + `final/NMS/IK` + 多帧共识门禁接到 Task C/D 的 `motion.dry_run=true`、`gripper.backend=mock` 链路，先确保缺少共识时零运动、零夹爪命令。
2. **补充独立数据**：增加同一场景不同时刻、不同视角和移动物体后的采集，验证 5 帧共识是否能稳定复现；当前只有 8 个 IK 成功样本，不能据此调松 25 mm / 15° 门禁。
3. **修复 IK 收敛**：对帧 16、20 增加确定性种子、阻尼和初值搜索，但保持现有位置/姿态接受阈值不变。
4. **继续多帧融合**：在候选共识之外，评估目标/障碍点云的多帧鲁棒融合，减少深度噪声对接触、净空和开口搜索的影响。
5. **完成现场标定**：手眼外参、夹爪安装时钟、垫片堆叠、指零位、TCP 偏移、夹爪时钟、限位和控制柜通信都必须现场验证；未经用户明确授权不得发送运动或夹爪命令。
