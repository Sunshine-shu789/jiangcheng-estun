# ESTUN SGS Modbus/TCP 接入基线

## 1. 目的

这份基线把“文档里看到的地址”变成可执行、可审计、默认只读的软件层：

```text
严格 Modbus/TCP 客户端
→ SGS 寄存器 schema
→ 状态字解码
→ 本地假控制器
→ 只读探针
→ 双层写闸门
```

没有经过现场只读确认和显式审批前，任何任务程序都不能调用写接口。

## 2. 当前已确认的链路

- 控制器：埃斯顿 SGS，机器人 S3-60-G2。
- 官方通信口：`LAN3(Modbus)`。
- Modbus TCP 端口：`502`。
- 从站示例地址：`1`。
- 支持功能码：FC1、FC3、FC5、FC6。
- 字节序：大端。
- 控制指令：先写非零命令，再恢复 `0`，由控制器识别上升沿。

HMI 网页不是正式控制 API。即使电脑能打开 HMI，也不能据此认定 HMI
口已经转发 `502`、ROS UDP 或其他端口。

## 3. 地址基线

采用 Excel 的保持寄存器绝对地址作为软件基线：

| 名称 | 地址 | 权限 |
| --- | ---: | --- |
| 主版本 | `0x0000` | 只读 |
| 次版本 | `0x0001` | 只读 |
| 当前速度倍率 | `0x0008` | 只读 |
| 机器人模式 | `0x000E` | 只读 |
| 安全模式 | `0x000F` | 只读 |
| 状态字 | `0x0010` | 只读 |
| 机器人命令 | `0x0100` | 读写 |
| 速度倍率命令 | `0x0103` | 读写 |
| 控制柜 DO | `0x1002` | 只读 |
| 法兰 DO | `0x1003` | 只读 |
| 控制柜 DO 命令 | `0x1300` | 读写 |
| 控制柜 DO 掩码 | `0x1301` | 读写 |
| 法兰 DO 命令 | `0x1302` | 读写 |
| 法兰 DO 掩码 | `0x1303` | 读写 |

PDF 第十章里的 `16/17/18` 按“通用总线字段偏移”处理，不把它们当作
Modbus 保持寄存器 `0x0010/0x0011/0x0012`。已有控制器 FC3 日志中：

- `0x0000` 读到主版本 `1`；
- `0x0001` 读到次版本 `6`；
- `0x000E`、`0x000F` 在真实日志中为非零模式值；
- `0x1002` 能读到控制柜 DO。

这些证据支持 Excel 地址表，但在比赛现场仍要再做一次只读复核。

## 4. 状态字

| 位 | 含义 |
| ---: | --- |
| 0 | 急停 |
| 1 | 上电 |
| 2 | 拖动模式 |
| 3 | 运动中 |
| 8 | 仿真 |
| 9-10 | 程序状态 |
| 15 | 故障 |

程序状态：

- `00`：停止；
- `10`：运行；
- `01`：软件标记为 `paused_unconfirmed`，官方资料未完整确认；
- `11`：保留。

任何未定义位都会出现在 `unknown_mask` 中，程序不得自行猜测含义。

## 5. 三层安全边界

### 第一层：传输层

```python
ModbusTcpConfig(allow_writes=False)
```

默认禁止 FC5/FC6。只读探针永远不会把该值设为 `True`。

### 第二层：机器人命令层

```python
SgsControlClient(
    transport,
    allow_robot_commands=False,
)
```

即使传输层允许写，机器人命令层的默认值仍然是关闭的。

### 第三层：现场流程

- 未确认 `502` 可达：不进行实时探测。
- 未确认地址和固件：不写。
- 未接急停、未清空工作空间：不做写测试。
- 未验证写后回零：不允许任务执行器持有写能力。

## 7. 接上控制柜后的只读探测

必须先确认电脑网卡和控制器处于可通信网段，然后执行：

```bash
./bin/check_sgs_modbus_readonly \
  --host 192.168.101.100 \
  --port 502 \
  --unit-id 1
```

该命令只发送 FC3，不能写寄存器或线圈。现场需要记录：

- 实际使用的网口和链路；
- 固件版本；
- 模式、安全模式和状态字；
- DO 当前值和 DO 命令镜像；
- 是否出现 Modbus 异常码；
- 状态字是否出现未知位。

如果这条命令失败，不应继续尝试写命令；先解决物理网口、IP、路由、
Modbus 从站开关或权限问题。

## 8. 写测试的前置条件

以下条件全部满足后，才可以设计独立的写验收，且第一轮不能带负载、不能启动
机器人运动：

1. 现场只读探测通过并保存原始 JSON；
2. 控制柜型号、固件版本、HMI/LAN 物理口完全对应；
3. 地址表在现场逐项复核；
4. 急停由第二人守候；
5. 机器人处于允许的安全状态，工作空间无人；
6. 单独测试 `robotCommand` 写入后回零，且读回确认；
7. 断开客户端后控制器不会保留非零命令；
8. 任何超时都以 `StopProgram`、清命令和人工确认收尾。

当前没有实现或开放“现场写测试”命令，这是有意为之。

## 9. 控制器内部任务协议

应用寄存器地址不能凭空编造。控制器工程里必须先定义并分配：

| 字段 | 作用 |
| --- | --- |
| `request_sequence` | 上位机请求序号 |
| `program_id` | 固定动作程序编号 |
| `target_arguments` | 目标位姿或程序参数 |
| `request_latch` | 新请求锁存 |
| `ack_sequence` | 控制器确认序号 |
| `controller_state` | Idle/Busy/Done/Fault |
| `progress` | 当前步骤 |
| `fault_code` | 故障码 |
| `heartbeat` | 双方存活心跳 |

推荐握手：

```text
上位机写参数
→ request_sequence +1
→ request_latch=1
→ 控制器确认 ack_sequence
→ 上位机清 request_latch
→ 控制器执行固定 MoveJ/MoveL 程序
→ 上位机轮询 Busy/Done/Fault
→ 超时则 StopProgram + 清命令 + 故障日志
```

只有在控制器程序里实现看门狗，才能防止上位机断线后继续执行。

## 10. 还没解决的事项

- `HMI` 物理口是否就是 `LAN3(Modbus)`，以及是否转发 `502`。
- SGS 当前固件版本是否与本项目目标版本一致。
- `paused_unconfirmed` 的实际位组合。
- 控制柜 DO 与末端 DO 的 PNP/NPN 最终接线语义。
- 自定义任务握手寄存器的地址。
- 第一次受控写测试。
- 夹爪最终走 USB/TTL 原生协议还是控制柜 DO。

在这些事项完成前，抓取程序继续使用 `motion.dry_run: true` 和
`gripper.backend: mock`，不会因这次 Modbus 基线变更而获得真实运动权限。
