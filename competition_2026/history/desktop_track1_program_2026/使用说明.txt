赛道一比赛程序
================

这个文件夹包含赛道一程序代码、模型、配置、日志和五个独立任务启动程序。
任务A固定使用旧的“视觉识别”；任务B/C/D/E使用新的抓取识别、IK、运动和状态机核心。

一、启动任务
------------
直接双击对应程序，不需要在终端输入命令：

  任务A_十点位巡检.desktop
  任务A_视觉识别.desktop
  任务B_五点位拾放.desktop
  任务C_无序抓取.desktop
  任务D_未知物体抓取.desktop
  任务E_顺序抓取.desktop

任务A有两个入口：

1. 任务A_十点位巡检.desktop
   - 机械臂以启动时的六轴位姿为起点，巡检10个停点位，最后自动回到启动
     时的精确关节姿态。
   - J1在 [-135°, +135°] 的270度安全范围内运行双弧：第1弧从 +135° 到
     -135°，第2弧从 -135° 回到 +135°，每个弧布置5个点。
   - 第1弧的J2相对启动姿态 +15°，第2弧的J2相对启动姿态 -9°；第5点到
     第6点保持J1在 -135°，通过J2的24°切换形成两条半径弧。
   - J1-J4允许运动，当前点位由J1和J2完成双弧巡检；J5、J6在每个目标中
     精确复制启动反馈并全程锁定，避免夹爪腕部关节动作。
   - 启动后先一次性预检查10个巡检点和第11个“回启动位”目标，包括FK、
     工作空间、关节限位、单步角度和TCP相邻距离。任何一项失败都不会发送
     第一段运动命令。
   - 固定读取旧版“任务A 视觉识别”的实时结果，不启动新的“抓取识别”，
     也不加载 models/best.pt。
   - 十类比赛物品全部纳入识别范围：Cheez-it、Starkist_Tuna、Scissors、
     Frenchs_Mustard、Tomato_Soup、Foam_Brick、Clamp、Plastic_Banana、
     Mug、meat_can。
   - 每个点位最多观察10秒，连续3帧确认十类中的任意物品后，机械臂在原地
     停3秒，再自动前往下一点；不会等待操作员按回车，也不会因为物品一直
     可见而重复运动或死锁。
   - 某点10秒内没有确认物品时，程序记录该点未命中并继续下一点；只有相机、
     旧视觉HTTP或机械臂通信故障才中止任务。
   - 该巡检入口不会发送夹爪命令。

2. 任务A_视觉识别.desktop
   - 打开旧版“视觉识别”，只做相机识别和观察。
   - 不移动机械臂，适合现场快速确认相机和模型。

任务B的五轮流程：
- 每一轮只抓取视觉确认过的当前点位物品。
- 开局先观察当前视野；未确认香蕉时，机械臂会依次移动到当前点位上方的
  多个安全观察位置继续寻找，每到一个位置重新识别。搜索不到时回到初始
  观察位姿，不会因为单帧误识别而直接抓取。
- 抓取后回到本轮实际抓取位置释放，不移动到固定投放槽。
- 释放并退开完成后，才等待视觉确认下一个点位的物品。
- 旧点位仍能看到已放回物品时，不会开始下一轮，也不会发送下一轮运动命令。
- 下一点没有确认时持续等待；任务停止或故障时才退出。
- 五个点位全部完成后程序退出。

任务B/C/D/E：
- 启动后自动使用新的持续实时识别，机械臂搜索、运动、靠近和夹取期间
  识别窗口都会持续刷新，可以一直观察。
- 桌面的“抓取识别”也可单独打开，用于手动观察；它本身不会移动机械臂。
- 任务运行时不要同时打开“视觉识别”或单独的“抓取识别”，D405只能由
  一个程序占用。

二、停止任务
------------
正常停止：双击“停止当前任务.desktop”。
该入口会停止当前任务、旧版“视觉识别”和单独的“抓取识别”。
紧急停止：立即按下机械臂硬件急停按钮。

三、当前安全状态
----------------
任务A正式入口使用 config/track1_task_a_legacy.yaml，当前
motion.dry_run: false，属于真机模式。双击后必须先在安全确认窗口确认控制器
处于 AutoReady、无故障、急停可用且工作区无人，程序才会继续。
- 十点位路线、最后回原点和J5/J6锁定会在第一段运动前全部预检查；
- 预检查或通信检查失败时，机械臂不会运动；
- 任务A巡检本身不会发送夹爪命令，夹爪保持当前状态；
- 程序内置配置和自动测试使用 dry-run 副本，不用于现场启动。

每次启动任务前程序都会进行环境检查。同一时间只允许一个任务运行，避免两个
任务同时抢占相机和机械臂。

任务A巡检和B/C/D/E启动时，程序会自动检查机械臂状态桥接：
- 桥接已运行时不重复启动；
- 桥接未运行时自动启动，并等待 /RobotInfo 到位；
- 本次任务启动的桥接会在任务结束后自动关闭；
- 若 12 秒内收不到状态，会弹出错误窗口，不再直接以一个一闪而过的
  英文异常结束。
控制器侧需保持“设置 -> ROS”的目标 IP 指向本机 UDP 9006 端口。

四、任务A十点位巡检参数
------------------------
在 config/track1_task_a_legacy.yaml 的 task_a.patrol 中设置：

  mode: joint_arc                  使用关节双弧巡检
  position_count: 10               共10个停点位
  movable_joints: [1, 2, 3, 4]     J1-J4允许运动
  joint1_targets_deg:              J1双弧绝对角目标
    [135, 67.5, 0, -67.5, -135,
     -135, -67.5, 0, 67.5, 135]
  joint_offsets_deg:               J2/J3/J4相对启动姿态偏置
    第1弧 [15, 0, 0]，第2弧 [-9, 0, 0]
  min_move_distance_m: 0.15        相邻TCP最小距离
  joint_max_step_deg: 2.0          关节插补单步上限
  settle_s: 0.5                    到位稳定时间
  post_detection_dwell_s: 3.0      确认物品后原地停留时间
  return_to_start: true            第10点后回到启动关节位姿

视觉后端和十类白名单必须保持为：

  backend: legacy_http
  target_class: ""
  classes:
    - "1-Cheez-it"
    - "2-Starkist_Tuna"
    - "3-Scissors"
    - "4-Frenchs_Mustard"
    - "5-Tomato_Soup"
    - "6-Foam_Brick"
    - "7-Clamp"
    - "8-Plastic_Banana"
    - "9-Mug"
    - "10-meat_can"

五、真机启用
------------
完成手眼标定、真实夹爪接线和现场安全验证后，由维护人员修改：

  任务A：config/track1_task_a_legacy.yaml
  任务B：config/track1_task_b_live.yaml
  任务C/D/E：config/track1_live.yaml

确认以下内容：
  1. motion.dry_run 改为 false
  2. gripper.backend 改为真实夹爪后端并填写参数
  3. pose.extrinsics_file 改为正式手眼标定文件
  4. task_b_place_poses.yaml 改为现场五个抓取点的参考坐标
  5. target_order.yaml 和任务E顺序一致

之后双击任务程序时，会先弹出真机安全确认窗口：
确认控制器为 AutoReady、无故障、急停可用、工作区无人后，点击“开始任务”。

六、目录说明
------------
bin/      五个任务启动程序和公共启动器
app/      完整程序源代码
config/   相机、机械臂、夹爪和任务配置
models/   B/C/D/E新的抓取识别模型（任务A不使用）
logs/     每次任务的终端日志和截图
state/    当前运行任务的进程状态

七、重要限制
------------
任务A的10点双弧路线、第11段回原点、J5/J6锁定、识别后停3秒、
旧视觉HTTP适配和十类覆盖统计已经完成自动测试及离线起点预检。
第一次任务A真机巡检仍必须由维护人员守急停；启动时J1必须位于 +135° 一侧
（最近记录的起点 J1≈93.32° 已通过预检）。若现场起点导致第一点需要超过
60°或路线工作空间预检失败，程序会拒绝运动，此时应重新摆位后再测试。

当前B/C/D/E已具备任务入口和状态机框架，但尚未完成真实手眼标定、
真实夹爪和现场点位验证。请勿把 motion.dry_run 直接改成 false 后试抓取。
