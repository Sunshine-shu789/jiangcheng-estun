# MS42DC V3 夹爪 Linux 通信诊断记录

日期：2026-10-18  
设备：WHEELTEC FAE 二指柔性夹爪 / MS42DC 步进电机驱控一体板 V3  
USB：`1a86:55d4`（CH9102），序列号 `5CF0022485`

## 当前结论

**夹爪硬件、12V 供电、接线和拨码基本正常，不能判定为硬件故障，也不需要按此记录联系售后返修。**

依据：用户已在 Windows 环境下确认夹爪能够正常运动。当前问题限定为 **Linux 串口控制通路尚未打通**，需要继续对比 Windows 成功时的软件和串口参数。

## Linux 当前状态

- 设备可正常枚举为 CH9102：`1a86:55d4`。
- 已临时加载 WCH 官方 `ch343` 驱动 V2.2。
- 当前设备节点：`/dev/ttyCH343USB0`。
- 稳定别名：`/dev/motor_serial -> ttyCH343USB0`。
- 权限：`root:dialout 0660`。
- 串口参数：115200、8 数据位、1 停止位、无校验、无硬件流控。
- 官方协议与 ROS2 源码中的帧格式、BCC 异或校验和 115200 波特率均已复核。

> 说明：当前 `ch343` 驱动是临时加载状态，重启后可能恢复为 `ttyACM0` / `cdc_acm`。在 Linux 动作验证成功前，不应据此认为问题已经永久解决。

## 已完成的 Linux 测试

### 状态请求

```text
7B 01 00 00 00 00 00 00 00 7A 7D
```

在 `cdc_acm` 和 `ch343` 两种驱动下均未收到状态回包。USB 抓包确认请求已经作为 Bulk OUT 数据发到 CH9102，但未看到 Bulk IN 回包。

### 小行程动作

曾发送过 5°、180° 等位置控制帧，用户确认没有可见动作。需要说明的是，180° 仍可能小于夹爪有效可见行程，不能单独据此判断协议失败。

### 完整行程动作

按用户手册完整行程张开帧发送：

```text
7B 01 02 00 20 46 50 01 2C 63 7D
```

含义：地址 1、位置模式、逆时针张开、32 细分、1800°、30 rad/s。发送命令已成功写入串口；随后保持串口打开 6 秒，仍未收到任何串口回包。是否产生可见动作待用户现场确认。

## 与 Windows 成功环境的待对比项

下一步必须获取 Windows 成功时的以下信息：

1. 使用的是 WHEELTEC 串口调试助手、WHEELTEC 上位机、ROS，还是其他程序。
2. Windows 中使用的 COM 口号。
3. 波特率、数据位、停止位、校验位和流控设置。
4. 夹爪拨码开关 1、2 的实际状态。
5. 点击运动时发送的完整十六进制数据。
6. 是否收到夹爪回复；若有回复，记录完整十六进制帧。
7. 最好提供 Windows 软件界面和拨码状态截图。

## 可能原因（按优先级）

1. Windows 成功时使用的拨码模式与 Linux 当前模式不同。
2. Windows 软件发送了额外的初始化/模式切换命令，而当前 Linux 只发送了运动帧。
3. Windows 实际发送的运动帧与本记录中的官方普通串口帧不同。
4. CH9102 在 Windows 与 Linux 下的 UART 初始化或控制线行为不同。
5. 夹爪当前未处于 USB 串口控制所需的拨码状态，或 Linux 测试期间供电状态发生变化。

## 后续处理原则

- 在取得 Windows 成功参数前，不反复盲目发送相同帧。
- 不修改夹爪固件，不进行重新烧录。
- 动作测试时保持夹爪周围无遮挡，并先使用张开方向或小角度测试。
- 只有 Linux 动作验证成功后，才将任务 B 的 `backend` 从 `mock` 切换到真实夹爪，并再永久安装 `ch343` 驱动。
