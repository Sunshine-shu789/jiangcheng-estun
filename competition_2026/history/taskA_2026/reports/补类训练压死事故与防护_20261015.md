# 补类训练「分类行压死」事故与防护（2026-10-15）

## 事故现象

泡沫砖（class 5 = 6-Foam_Brick）首次补入 204 个样本后微调（v19，lr≈7e-4，
65 epoch），训练损失正常、旧类指标正常，但泡沫砖在 68 帧评估集上
**0 检出**（连 conf=0.0001 都无该类输出）。

## 根因（已量化验证）

- 类在历史数据集中长期 0 样本时，训练持续用负样本压该类 cls head 的 bias。
  实测 v18 权重 class 5 三尺度 bias = **-22.78 / -14.77 / -20.08**
  （sigmoid ≈ 4e-7，几乎永远不输出）。
- 首补样本后微调：每步 bias 位移 ≈ lr ≈ 7e-4；65 epoch 中该类 batch 约
  1700 个，理论上限 +1.2 个 logit，而需要 **+20** 才能回到可输出区间。
- 结果：bias 65 epoch 后几乎没动（<0.01），该类永远 0 检出。
- 旁证：cls head 其他权重行在变化（0.1~0.6），数据、标签、cache 全部正常。

## 修复（v20 起点）

1. 体检：`python check_newclass_prior.py --weights <起点.pt> --data <新data.yaml> --history <旧data.yaml>`
   精确输出「新补类且压死」清单。
2. 重置该类分类行：weight 行归零 + bias → -4.6（sigmoid≈0.01，正常先验）：
   - 一体化：`check_newclass_prior.py --fix <输出.pt> ...`
   - 手工单类：`python reinit_cls_row.py --src <起点.pt> --dst <输出.pt> --class-index 5`
3. 从修复起点按原配方微调（probe 用大 lr 3e-3 验证可学性，正式训练用保守 lr）。
4. 训练后按常规评估（新类 68 帧 + 回归集），确认新类检出与旧类不掉点。

## 以后的标准流程（新增/补类必做）

1. **训练前**：跑 `check_newclass_prior.py`（带 `--history`），出现
   WARN(新补类且压死) → 先 `--fix` 生成起点，再开始训练。
   - 判据：历史样本数=0 且当前样本数>0 且 max(三尺度 bias) < -9.2。
   - 注意：正常低 bias 类（历史有样本、权重行已学会响应）**不需要**重置，
     避免误伤（如 v18 的 class 1/4/8）。
2. **训练后**：自动评估必须包含该类的专项目标集（本次为 68 帧泡沫砖集）
   与回归集（val214 / old72），确认「新类学起来 + 旧类不掉点」。
3. **评估口径**：多尺度（0.65/0.75）+ IoU≥0.75 通过率 + conf 0.25，
   与历史口径保持一致。
